title: Introduction

---

clawops provisions and operates **self-hosted OpenClaw** on AWS, GCP, Azure or any Linux box you
can reach over SSH.

It owns the layer between "I want an agent" and "an agent is running": the VM, the firewall, the
container, secrets, health checks and the upgrade path. It does not author your agents — that is
OpenClaw's job.

## The shape of it

<Cards>
  <Card title="Plans you read before they run" href="/docs/plan-apply">
    `clawops plan` emits a JSON artifact you review, diff and commit. `clawops apply` executes
    exactly that. Nothing reaches your cloud account straight from a natural-language instruction.
  </Card>
  <Card title="Embedded Pulumi" href="/docs/installation">
    The Automation API runs in-process — no separate Pulumi install, no state backend to stand up
    before your first deploy.
  </Card>
  <Card title="Typed MCP tools" href="/docs/mcp">
    Every operation is a tool with explicit safety annotations, so a coding agent knows what is
    read-only, what is destructive, and what needs confirmation.
  </Card>
  <Card title="Known limits" href="/docs/limitations">
    Single-node, no TLS automation, no cost estimation. Worth reading before you install it.
  </Card>
</Cards>

## Before you start

<Callout title="This line requires OpenClaw 2.0">
  clawops 2.x deploys OpenClaw `>= 2026.9.2` and refuses anything older. For OpenClaw
  `<= 2026.7.1-2`, use `npm install -g @clawops/cli@legacy`. Coming from 1.x?
  `clawops migrate` moves an existing deployment across, keeping its state and device identity.
  See [OpenClaw compatibility](/docs/openclaw-compatibility).
</Callout>
